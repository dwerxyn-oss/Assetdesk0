# AssetDesk

Текстовый Telegram-бот сервиса AssetDesk. Пользователь выполняет задания, получает внутренние Stars, приглашает друзей, запрашивает вывод награды и оставляет заявку на продажу Telegram Gift. Оценку, согласование и завершение сделки проводит администратор.

Бот не покупает и не продаёт NFT или Gifts на внешних площадках и не отправляет Telegram Gift сам. Выдача награды и оплата сделки выполняются вручную.

## Требования

- Python 3.11 или новее
- Telegram-бот, созданный через [@BotFather](https://t.me/BotFather)
- Аккаунт администратора (его числовой Telegram ID)

База данных MVP — SQLite. Отдельный сервер базы не нужен.

## Установка

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

Для проверок:

```powershell
.venv\Scripts\python -m pip install -r requirements-dev.txt
.venv\Scripts\python -m pytest -q
```

## Создание .env

Скопируйте пример и заполните значения:

```powershell
Copy-Item .env.example .env
```

```env
BOT_TOKEN=
ADMIN_ID=
BOT_USERNAME=
SUPPORT_USERNAME=AssetDeskOriginal

TIMEZONE=Europe/Moscow

FIRST_WITHDRAW_MIN=15
REGULAR_WITHDRAW_MIN=15

NEW_SELLER_LIMIT_USD=25
REGULAR_SELLER_LIMIT_USD=50
TRUSTED_SELLER_LIMIT_USD=100

REFERRAL_REWARD=2
REFERRAL_DAILY_LIMIT=30
DAILY_BONUS=2
```

`BOT_USERNAME` — username бота без `@` и без `https://t.me/`. Он нужен для реферальной ссылки.

Числа в примере — стартовые значения. Их можно менять в `.env` и перезапускать бота. Баланс и суммы наград хранятся целыми числами.

Необязательный `DATABASE_URL` переопределяет путь к базе. По умолчанию используется `data/assetdesk.db`.

Файл `.env` не коммитьте.

## Получение BOT_TOKEN

1. Откройте [@BotFather](https://t.me/BotFather).
2. Отправьте `/newbot` или откройте уже созданного бота через `/mybots`.
3. Скопируйте токен вида `123456:ABC...` в `BOT_TOKEN`.

Токен не записывается в исходный код и вырезается из логов, если Telegram вернёт его в тексте ошибки.

## Настройка ADMIN_ID

`ADMIN_ID` — числовой Telegram ID человека, которому доступна команда `/admin`.

Узнать ID можно через [@userinfobot](https://t.me/userinfobot): отправьте ему любое сообщение и скопируйте `Id`.

Админ-панель открывается только этому ID и только в личном чате с ботом. Обычный пользователь, отправивший `/admin`, получит отказ.

## Запуск

```powershell
.venv\Scripts\python -m app
```

При старте создаётся база, регистрируются команды `/start`, `/menu`, `/help`, а для администратора ещё `/admin`.

Один процесс на одну базу. Повторный запуск с тем же файлом SQLite не предусмотрен: запись сериализуется внутри процесса.

Бонус дня считается по календарной дате в `TIMEZONE`. Для Windows в зависимостях есть `tzdata`, чтобы таймзона `Europe/Moscow` находилась без системных IANA-данных.

## Создание первого задания

1. Запустите бота и отправьте ему `/admin` с аккаунта `ADMIN_ID`.
2. Откройте **Задания** → **Создать**.
3. Введите название, описание (или `-`), награду в целых Stars.
4. Выберите тип **Подписка на канал**.
5. Укажите `@channel` или числовой id канала.
6. Укажите лимит выполнений: `0` — без лимита.

Награда за одно задание начисляется пользователю один раз. Повторная проверка не создаёт вторую транзакцию.

## Настройка канала

Для задания «Подписка на канал» бот должен состоять в канале и иметь право видеть участников. Добавьте бота администратором канала.

Пользователь нажимает «Подписаться», затем «Проверить». Бот вызывает `getChatMember`. Если пользователь в канале, награда начисляется. Если нет — бот просит выполнить условие.

Если у бота нет прав или канал указан неверно, пользователь видит короткое сообщение, а причина пишется в лог без токена.

Тип «Открыть канал» тоже привязан к каналу, но награда начисляется после нажатия «Проверить» без проверки членства. Используйте его только если проверка подписки не нужна.

## Настройка наград

Каталог наград — список вариантов, которые администратор может выдать вручную. Это не отправка Telegram Gift через API.

В `/admin` откройте **Награды**:

- добавьте название, описание, стоимость в Stars и внутреннюю пометку;
- измените стоимость или описание;
- выключите награду, чтобы она пропала из пользовательского списка.

Пользователь видит только активные награды. В тексте нет обещания конкретного Gift, пока администратор сам не завершил заявку на вывод.

## Настройка seller limits

Лимиты в `.env` — внутренний ориентир в целых долларах, без конвертации валют:

| Уровень | Переменная |
| --- | --- |
| Новый | `NEW_SELLER_LIMIT_USD` |
| Постоянный | `REGULAR_SELLER_LIMIT_USD` |
| Доверенный | `TRUSTED_SELLER_LIMIT_USD` |

Новый пользователь получает лимит `NEW_SELLER_LIMIT_USD`. Смена уровня сама лимит не меняет. В карточке пользователя администратор задаёт уровень, лимит и отметку ручной проверки отдельно. Кнопка применения лимита уровня подставляет значение из конфига для текущего уровня.

Успешная сделка увеличивает счётчик сделок и объём один раз, когда администратор переводит заявку в `completed`. Лимит при этом не повышается.

## Основные команды

| Команда | Кто | Что делает |
| --- | --- | --- |
| `/start` | все | регистрация и главное меню; `ref_USERID` сохраняет пригласившего |
| `/menu` | все | главное меню, сбрасывает текущий шаг |
| `/help` | все | помощь и FAQ |
| `/cancel` | все | отмена текущего шага |
| `/admin` | только `ADMIN_ID` | админ-панель |

Меню пользователя: заработать, бонус дня, вывести, продать подарок, пригласить друзей, баланс, история, помощь.

Реферальная ссылка: `https://t.me/BOT_USERNAME?start=ref_USERID`. Награда начисляется пригласившему один раз, когда человек впервые открывает бота по этой ссылке. Повторный заход и чужая ссылка после регистрации баланс не меняют. В день учитывается не больше `REFERRAL_DAILY_LIMIT` таких заходов. У пользователя может быть только один пригласивший.

Минимальный вывод: `FIRST_WITHDRAW_MIN` для первой успешной выплаты и `REGULAR_WITHDRAW_MIN` для следующих. Пока заявка в работе, сумма резервируется и не уходит во вторую заявку. Списание и транзакция `withdrawal` создаются только при статусе `completed`.

## Структура проекта

```text
app/
  main.py              запуск, команды, обработка ошибок
  config.py            настройки из .env
  constants.py         статусы и типы
  logging_setup.py     логи без токена
  db/                  модели и сессии SQLite
  services/            баланс, задания, вывод, сделки, статистика
  handlers/            пользовательские экраны
  handlers/admin/      админ-панель
  keyboards/           inline-кнопки и callback data
  states/              шаги FSM
  texts/               тексты сообщений
  middlewares/         сессия, пользователь, блокировка
  utils/               деньги, время, разбор ввода
data/                  файл базы
tests/                 проверки экономики и сделок
```

Любое изменение баланса проходит через таблицу `transactions`. Прямой записи в поле баланса из обработчиков нет.

## Как сделать backup SQLite

1. Остановите бота.
2. Скопируйте `data/assetdesk.db`.
3. Если рядом есть `data/assetdesk.db-wal` и `data/assetdesk.db-shm`, скопируйте их тоже или дождитесь, пока бот закроет базу и останется один файл `.db`.

Восстановление — это замена этих файлов при остановленном боте.

## Как добавить новые задания

В `/admin` → **Задания**:

- **Подписка на канал** — награда после проверки членства.
- **Открыть канал** — переход и отметка без проверки членства.
- **Своё** и **Партнёрское** — условие или ссылка в тексте; пользователь отмечает выполнение.
- **Рефералы** — цель: сколько приглашённых должны уже выполнить хотя бы одно задание.

Готовое задание можно изменить, выключить или архивировать. Удаление доступно, пока его никто не выполнил. Новые типы заданий добавляются в `app/constants.py`, сервис `app/services/tasks.py` и клавиатуру создания, без переноса остальной логики баланса.

## Что остаётся ручным

- Вывод Stars и выдача награды из каталога.
- Оценка, приём и оплата продажи Gift.
- Повышение уровня и лимита продавца.
- Продажа купленных подарков вне бота.

Пользователь не видит «выплачено», пока администратор не перевёл заявку в `completed`.
